# Analyze Requirement

For clear small requests, capture the outcome briefly and proceed; no separate analysis document is needed.
For ambiguous/substantial work, identify actor, goal, acceptance criteria, affected modules and material risks,
starting from the design spec and the roadmap tracker.
Inspect only relevant requirements and decisions. Ask only questions whose answers block correct implementation.
Use AGENTS.md to choose review depth; avoid expanding the requested scope.
If the requirement changes what the spec says, that is an owner decision to record in the spec with the date.
