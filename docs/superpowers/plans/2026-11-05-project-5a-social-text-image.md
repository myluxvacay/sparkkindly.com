# Project 5A: Social distribution, text and image posts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Each day a rule picks a few published items per platform (Instagram, Facebook first; TikTok and YouTube rows exist for 5B), a promotion agent writes the caption and hashtags, the server builds the link and branded image, and a worker posts at the configured time through the Meta Graph API, records the result and metrics, and cancels or flags posts if an item is unpublished. Items not picked are recorded as `skipped` with a reason. Nothing is ever posted for Kids.

**Architecture:** `lib/social/` (selection, copy validation, UTM links, adapters behind one interface, state machine; no Next.js imports) over a migration; agent role `promoter` with `/api/agent/promotions` (queue and copy submit) and per-entry subagent/command like the moderator; worker jobs `social-select`, `social-post`, `social-metrics`; admin page `/admin/social/`. Credentials come only from root-owned env files (never the database, repo or prompts). Behind `SOCIAL_ENABLED` plus per-platform enable switches in `/admin` (all off; nothing posts until the owner has the Meta approvals and sets the tokens).

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, zod, Vitest, Playwright + axe, `fetch` with `AbortSignal.timeout`. Existing: `lib/jobs/{run-job,guards}.ts`, `worker/main.ts`, `lib/agents/*`, `agents/mcp/*`, `lib/public/template-image.tsx` and `app/api/template-image`, `lib/items/repo.ts` (`transitionTx`), `lib/admin/*`, `lib/email.ts`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 5 Part A (daily selection, promotion agent, worker, UTM), `.claude/rules/{ai-governance,security,media-storage,data-isolation}.md`.

## Global Constraints

- **Never Kids:** an item is ineligible if its world is Kids, its audience is `kids`, or its risk tier is `kids`; checked at selection, at copy submission, and again at post time. Only `published`, non-archived items qualify; the post-time check re-reads the item and cancels the distribution if it is no longer eligible.
- **Selection (daily, per enabled platform, pure ordering function plus SQL):** candidates are eligible items published in the last 3 days with no distribution for that platform yet; rotate worlds (the world with the oldest last successful post on that platform goes first); prefer playable kinds (`quiz`, `game`) over articles; among equals prefer topics with more answers in the last 14 days (`item_responses`), then newest. Pick up to the platform's `daily_cap`; every other candidate gets a `skipped` row with a fixed reason (`cap_reached`, `world_rotation`, `not_playable`, `lower_topic_popularity`). The owner can hand-pick an item for a platform in `/admin`, which bypasses the rotation but not the eligibility rules or the cap.
- **Caps and times in `/admin`:** `social_platforms (platform PK in instagram|facebook|tiktok|youtube, enabled boolean DEFAULT false, daily_cap int, post_time_utc time, updated_at)` seeded with caps IG 2, FB 3, TikTok 1, YouTube 1; cap 0 to 10; the cap is enforced again by the poster per UTC day by counting `posted`/`scheduled` rows.
- **`distributions`:** `id, item_id (cascade), platform, day date, status (selected|skipped|copy_ready|scheduled|posting|posted|failed|cancelled|flagged), skip_reason, caption, hashtags jsonb, link, image_url, scheduled_for, posted_at, post_url, external_id, metrics jsonb, metrics_at, attempts, last_error, version, created_at, updated_at`, UNIQUE (item_id, platform). Transitions via a pure state machine; every transition is an atomic conditional UPDATE.
- **Link and UTM:** the server builds `https://<site>/<world>/<slug>/?utm_source=<platform>&utm_medium=social&utm_campaign=<world>-<item slug>`; the agent never writes a URL. Social landings are counted privately: item pages increment an aggregate `social_visits (day, platform, item_id, visits)` row when the query has a valid `utm_source` from the allowed list; no cookie, no IP, no identifier, no change to the page for the visitor.
- **Promotion agent (untrusted):** role `promoter` (CHECK extended by migration), no world; `GET /api/agent/promotions` returns up to 5 `selected` entries `{ id, version, platform, limits, world, kind, data: { title, summary, body excerpt (first 600 characters) } }` (item text only inside `data`); `POST /api/agent/promotions/copy` takes `{ id, version, caption, hashtags }` validated by zod and server rules: caption 1 to 2,000 characters (Instagram 2,200 including hashtags; Facebook 1 to 500 by our own choice), at most 8 hashtags matching `^[\p{L}\p{N}_]{2,30}$`, **no URLs, link-like text, `@` mentions, control or bidi characters**, no blocked words, no medical/legal/financial claims language list is not required but the reviewer prompt covers tone; stale `version` = 409; accepted copy moves `selected` -> `copy_ready` -> `scheduled` (with `scheduled_for` = the day's `post_time_utc`, or the next valid time when already past, never after 20:00 UTC). Role separation both ways (promoter keys only on promotion routes; content, moderation and reviewer keys refused there).
- **Share image:** a branded 1080x1350 image from the existing template (title, world colour, logo, no personal data, no faces, no user content) served from our own site at a public https URL (`/api/template-image/...?format=social`); Instagram needs JPEG: produce JPEG output (use an already-installed library; if none exists, add the smallest dependency and record the licence) and have the staging dry run verify it; the image URL is built by the server.
- **Adapters (`PlatformAdapter { post(d, deps): Promise<{ externalId; url }>; metrics(d, deps): Promise<{ reach?: number; likes?: number; comments?: number }> }`):** `meta.ts` implements Instagram (create media container with `image_url` + caption, poll status with a bounded wait, publish) and Facebook (Page photo post with caption and link in the message); tokens and ids come from `META_PAGE_ACCESS_TOKEN`, `META_PAGE_ID`, `META_IG_USER_ID` env vars read at call time; missing credentials = the distribution stays `scheduled` and `/admin` shows "no credentials", never a crash. Every call uses `AbortSignal.timeout(15000)`; transient errors (HTTP 429/5xx/network) retry 3 times with 5-minute spacing (attempts counted), then `failed`; permanent errors (4xx other than 429, expired token) fail at once and raise one digest line. Responses and errors are logged without tokens, captions or URLs with tokens. TikTok/YouTube adapters are 5B.
- **Poster safety:** claims one row at a time with `UPDATE ... WHERE status='scheduled' AND scheduled_for <= now() RETURNING` (status -> `posting`), so two workers never double-post; a crash mid-post leaves `posting`, which a recovery step turns into `flagged` for the owner after 30 minutes (never auto-retried, because the platform may have posted); the poster refuses when the item is ineligible at post time.
- **Unpublish:** when an item moves to `archived` (or is deleted), its `selected|copy_ready|scheduled` distributions become `cancelled`; `posted` ones become `flagged` (shown in `/admin/social/` as "remove manually from the platform") and add a digest line. Done in the same transaction as the item transition.
- **Metrics:** daily job reads reach/likes/comments for posts of the last 7 days into `metrics`; failures are logged and never block posting.
- **Admin `/admin/social/`:** platform switches, caps and times (audited); today's and recent distributions with status, skip reason, link, post URL, error; hand-pick, retry (failed -> scheduled once), cancel; visits per platform per item; "no credentials" banner. Actions audited (`social.platform_set`, `social.pick`, `social.retry`, `social.cancel`).
- **AI governance:** copy is validated server-side; the agent cannot post, schedule, change caps, pick items or touch Kids; the poster publishes exactly the stored, validated caption. A weekly spot-check of posted captions is recorded in OPERATIONS.
- **Privacy/security:** no third-party scripts or requests on the site; outbound calls only from the worker to Meta with bounded timeouts; no personal data in captions or images; tokens never in logs/DB/repo. Migration additive with rollback header. No AI trailers; do not push.

## Review Focus

- No Kids item (by world, audience or risk tier, including after an edit or world move) can be selected, given copy, scheduled or posted; the poster re-checks.
- No double post: two concurrent worker ticks, a crash during `posting`, a retried failure after a partly successful platform call.
- Injection through item text into the promotion agent cannot create URLs, mentions, hashtags outside the pattern, or alter the schedule/platform; the posted text equals the stored validated caption.
- Unpublishing between scheduling and posting, or after posting, is handled (cancelled/flagged) and shown to the owner.
- Missing/expired credentials and platform outages degrade to visible states without leaking tokens or blocking other platforms.
