# Project 5B: Social distribution, the video jobs queue (TikTok and YouTube) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** For each selected `video_script` item the promotion agent writes a complete video brief (narration, shot list, on-screen text, per-platform caption and hashtags); the brief appears as a job in `/admin`; whoever makes the video (the owner, a person or a tool) uploads the finished file to the job; after validation and the owner's explicit approval the worker posts it to TikTok and YouTube Shorts and records the result and metrics. Making the video stays human or tool work by design.

**Architecture:** Builds on 5A (`docs/superpowers/plans/2026-11-05-project-5a-social-text-image.md`): the same `social_platforms`, `distributions` state machine, poster, cancel/flag hooks, metrics job and promoter role. New: `video_jobs`, `lib/social/video/` (brief rules, upload and validation, jobs), adapters `adapters/tiktok.ts` and `adapters/youtube.ts`, a file-based `TokenStore`, admin pages `/admin/social/videos/`. Behind `SOCIAL_ENABLED` plus the per-platform switches (off). **Nothing is posted until the owner has the TikTok and Google approvals and sets credentials.**

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, zod, Vitest, Playwright + axe, Node streams, `fetch` with bounded timeouts. Existing: `lib/social/*` (5A), `lib/agents/*`, `agents/mcp/*`, `lib/admin/*`, media rules in `.claude/rules/media-storage.md`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 5 Part B, `.claude/rules/{media-storage,accessibility,security,ai-governance}.md`.

## Global Constraints

- **Source items:** `video_script` items that are eligible for social by the 5A rules (never Kids by world, audience or risk tier; `published` or `scheduled` status as the world's pipeline leaves them: the builder checks how `video_script` items are stored and records a Ruling). A selected video item for TikTok or YouTube becomes a `video_jobs` row in `brief_pending` (cap per platform per day from `social_platforms`, TikTok 1, YouTube 1; the same rotation and skip-reason rules as 5A).
- **Brief (promoter role, untrusted):** the existing promoter queue also returns `brief_pending` video jobs; `POST /api/agent/promotions/brief` takes `{ id, version, narration, shots[], onScreenText[], captions: { tiktok, youtube }, hashtags[], durationSeconds }` validated by zod: narration up to 1,200 characters, 3 to 12 shots of up to 200 characters, on-screen text lines up to 60 characters, `durationSeconds` 15 to 60, captions and hashtags under the 5A caption rules (NFKC, no URLs, mentions, dot-like characters, bidi/control/default-ignorable characters, blocked words, at most 8 hashtags, TikTok caption up to 2,000, YouTube title up to 100 and description up to 1,000 as separate fields). The brief includes the brand assets list (logo path, world colour, template frame names) built by the server, not the agent. Stale version 409; replay idempotent. State -> `brief_ready`.
- **Captions are mandatory:** all video requires captions. A job cannot be approved for posting without a caption file (WebVTT or SRT, up to 200 KB, text only, validated) for YouTube, and an owner declaration that captions are burned into the TikTok video; the job page states this plainly.
- **Upload (media-storage flow):** `/admin/social/videos/<id>/` accepts the finished file from an authenticated admin only (same-origin, session, CSRF, second factor like every admin write): intent (the job id and a declared size) -> size-limited streaming upload (maximum 256 MB, enforced while streaming, not after buffering) into a **quarantine directory** `SOCIAL_MEDIA_DIR/quarantine/` (default under `/opt/sparkkindly/shared/media/`, configurable for tests) -> validation (extension `.mp4` only; magic bytes `ftyp` container; MIME sniffed by content, not the header; name replaced by a server-generated name, no path from the client; SHA-256 recorded; duration/resolution read with `ffprobe` when present on the VM, else only the container checks and a warning in the job; reject files that are not MP4/H.264) -> **the owner's explicit "approve for posting" click** (version-bound to the checksum shown) -> moved to the published media folder and the distribution becomes `scheduled`. A file is never served publicly; platforms receive it by upload from the worker. The database stores path, checksum, size, origin `owner-supplied` and licence note, never the bytes. Files are reopened and re-hashed after the move before success is claimed. Quarantine files older than 7 days are purged by a job. Uploaded media and any media directory are never committed (the folder is outside the repo; `.gitignore` entries added for any local test directory).
- **TikTok adapter** (Content Posting API, file upload flow: init, chunked upload with bounded per-chunk timeouts, status poll, bounded wait) and **YouTube adapter** (Data API v3 resumable upload `videos.insert`, `selfDeclaredMadeForKids: false`, category set by the server, captions uploaded with `captions.insert`) implement the 5A `PlatformAdapter` interface with injected `fetch`. Posts are created as the most restrictive visibility the platform allows until the app is approved (TikTok unaudited posts are private: the job shows "private until TikTok approves the app"; YouTube `privacyStatus` follows an env switch `YOUTUBE_PRIVACY` default `private`, owner flips to `public` after reviewing). Quota/limit errors (YouTube 403 quotaExceeded, TikTok rate limits) are transient with a longer backoff and surface one digest line; never retried after a possibly-successful final call (flag instead, as in 5A).
- **Credentials and token rotation:** client ids/secrets and initial refresh tokens come from root-owned env files; rotating tokens (TikTok refresh tokens rotate; access tokens expire) are kept in a file-based `TokenStore` at `SOCIAL_TOKEN_FILE` (default `/opt/sparkkindly/shared/social-tokens.json`, mode 0600, owned by the service user, atomic write via temp file + rename, never in the database, repo, logs, prompts or the export). Concurrent refresh is guarded by a lock file; a failed refresh marks the platform "needs re-authorisation" in `/admin/social/` and stops posting for that platform.
- **Admin:** `/admin/social/videos/` lists jobs with state, brief (rendered as plain text, copy button not required), upload form, validation result, checksum, approval button, post URL, errors; actions `video.upload` (the streaming route), `video.approve`, `video.cancel`, `video.retry`, `video.captions_upload`; all audited. A "maker" note field records who made it (free text up to 100 characters, owner only). The owner decision on who makes videos (tracker 5.8) is recorded outside code.
- **Unpublish:** archiving the source item cancels unposted jobs (and deletes their quarantined/approved file after 30 days) and flags posted ones, exactly like 5A.
- **Privacy:** no personal data in briefs or captions; no third-party requests from the site; the worker is the only caller of TikTok/Google; tokens never logged; the data inventory lists the media folder and token file.
- Migration additive with rollback header. No AI trailers; do not push.

## Review Focus

- No Kids-derived or ineligible video can be briefed, uploaded, approved or posted; the poster re-checks eligibility; a file can never be posted without validation, captions and the owner's checksum-bound approval.
- Upload hardening: path traversal, double extensions, polyglot files (an MP4 header followed by other content), oversize streams, concurrent uploads to one job, aborted uploads leaving partial files, quarantine escape, symlinks, disk exhaustion (global quarantine quota), serving quarantined/approved files publicly (must be impossible).
- Token store: file permissions, atomic updates, refresh races between two worker ticks, tokens in logs/errors/digest, behaviour when the file is missing or corrupt.
- No double upload/post after a crash mid-upload; resumable upload sessions are not blindly retried.
- Injection through briefs or captions cannot produce URLs/mentions or alter platform, schedule or file paths; the brief text renders as plain text in `/admin`.
