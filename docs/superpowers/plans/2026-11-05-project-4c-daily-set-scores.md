# Project 4C: Circle interests, daily set, scoring and leaderboards Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Each circle picks worlds and topics; every day it gets a set of playable items drawn from them (child-safe when a child profile is in the circle); members answer on the normal item pages; the circle shows daily, weekly, monthly and all-time tallies with shared ranks, visible only to its members.

**Architecture:** `lib/circles/interests.ts`, `lib/circles/daily-set.ts` (selection, pure ordering function plus SQL), `lib/circles/scores.ts` (tallies derived on read from `item_responses` joined to the set; nothing is double-stored, so a deletion or a corrected answer recomputes automatically), `lib/circles/rescore.ts`. Pages under `app/circles/[slug]/{set,scores,interests}/`. Behind `ACCOUNTS_ENABLED` and `CIRCLES_ENABLED`. Depends on plans 4A and 4B.

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, Vitest, Playwright + axe. Existing: `lib/public/reads.ts` (`visibleWhere`), `lib/public/scope.ts`, `lib/accounts/record-play.ts`, `item_responses`, `item_answers`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 4 ("Circle interests", "Child-safe sets", "Competitions", "Leaderboards", circle rules on re-scoring, ties, former members and bonus fill).

## Global Constraints

- Playable items only: `items.kind IN ('quiz','game','puzzle')` that have an `item_answers` row, status `published`, not archived.
- Set size 5 items a day (constant `SET_SIZE`). Chosen from the circle's topics and worlds; short of 5, filled from the circle's chosen worlds, then from any world, those marked `bonus`. A circle with no interests uses all worlds.
- **Audience is a safety filter:** a circle that contains any current child profile gets `kids` and `all` items only, on every read of the set (the stored set is re-filtered at read time with the circle's current make-up, so adding a child later hides any `adults` item at once and unscored). Other circles use the full scope for adults/teens as the rest of the site does (`currentScope` rules).
- The set for a circle day is created on first request and then fixed (unique on circle, day, position): same circle and day always return the same items. Ordering is deterministic from a hash of (circle id, day, item id); items shown to the circle in the previous 14 days are skipped unless needed to fill.
- The circle's day follows `circles.time_zone` (4A). The day key is the calendar date in that zone.
- Scoring (derived): a member earns `points_correct` (default 10, owner-tunable in `/admin`) per set item they answered correctly with `answered_at` inside that circle day; nothing for speed; one answer per item per profile (existing unique index). Answers made outside the circle day do not count. Members are accounts (`profile_id` null) and child profiles as separate members; former members (`left_at` set) keep their past points shown as "Former member"; account deletion removes their rows so totals drop.
- Ranking: competition ranking (1, 1, 3); ties share a rank. Tallies: day, ISO week and calendar month in the circle's zone, and all time; per-member and whole-circle totals.
- Visibility: scores, set and member names are visible to current members of that circle only (and to a child profile only for circles it currently belongs to). No public route exposes scores; a source-scan test forbids importing `lib/circles/scores` outside `app/circles/**` and `lib/circles/**`. Which answer a member chose is never shown, only points and answered/not answered.
- Re-scoring: changing an item's answer key (`item_answers.answer`) recomputes `item_responses.correct` for that item from the stored choice, and writes one `circle_notices` row for each circle that had that item in a set in the last 30 days (shown on the circle page; emailed in 4D). Existing answer storage must keep the chosen answer; if `item_responses` does not store the choice, add a nullable `choice jsonb` column in migration 016 (expand-only) written by the record path from now on and treat older rows as not re-scorable.
- A child-profile context (`getContext`) may open `/circles/<slug>/set/` and `/circles/<slug>/scores/` for circles its profile currently belongs to, read-only, and answer set items on the normal item page; it still cannot reach any circle write, invite, settings, member list beyond display names and scores, or anything else.
- Migration 016 additive with rollback header. No AI trailers; do not push.

## Review Focus

- A circle that has ever had a child profile never shows or scores an `adults` item to anyone while the child is a member; removing the child restores the full scope for later days only.
- Account B, a non-member and a left member read nothing (set, scores, notices); a forged circle slug or profile id in a request changes nothing.
- Sets are stable across calls, across a clock tick at midnight and across a time-zone-boundary member; a circle in Pacific/Auckland and one in America/Los_Angeles roll over at different instants.
- Zero-point, all-tied and one-member circles rank sanely; a deleted account's points vanish and ranks recompute; a corrected key flips `correct` and the notice appears once.
- The point value change in `/admin` is audited and bounded (0 to 100).
