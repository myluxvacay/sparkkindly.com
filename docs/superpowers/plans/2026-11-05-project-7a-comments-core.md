# Project 7A: Comments core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Signed-in members aged 16 and over can comment on published items outside Kids; a new account's comments are held (published by the moderation agent in 7B), a trusted account's appear at once after the server's mechanical checks; anonymous visitors can read published comments; a child profile never sees or posts comments; the owner can switch comments off per world or per item and set or ban an account's trust in `/admin`.

**Architecture:** `lib/comments/` (rules, checks, repo, trust; no Next.js imports) over migration 021; a comment section component on the item page; thin routes under `app/comments/`; admin actions in `lib/admin/actions.ts`. Behind `ACCOUNTS_ENABLED` AND a new `COMMENTS_ENABLED` flag (both off everywhere). Reporting and the moderation agent are 7B (`docs/superpowers/plans/2026-11-05-project-7b-comment-moderation.md`, written after this part lands).

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, Vitest, Playwright + axe. Existing: `lib/accounts/{policy,context,scope-next,limits}.ts`, `lib/items/blocked.ts`, circles' `cleanText` style of validation, `lib/admin/actions.ts`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 7 ("Who can comment", "Where", "Shape", "Trust levels", "Server checks"), section 4a.5 and `.claude/rules/{data-isolation,security,accessibility}.md`.

## Global Constraints

- Who: capability `public_comment` (16+ and adults; denied for 13-15 whatever the consent), verified account, not banned, adult context (a child profile context never posts and **never sees the comment section at all**: the section is absent from the HTML, not hidden by CSS).
- Where: only `published` items, never in the Kids world and never on an item whose audience is `kids`. **Ruling:** the spec's "off by default for Kids, owner can turn it on" conflicts with its "Kids items never carry comments for anyone" (4a.5); the safety statement wins and the admin toggle is not offered for Kids. Elsewhere comments are on by default; `worlds.comments_enabled` (default true, false for kids) and `items.comments_enabled` (nullable, null = inherit) are owner switches in `/admin`. When off, the section is absent and posting is refused; existing comments are kept but not shown.
- Anonymous visitors see published comments on non-Kids items (no posting). Pages that now vary by session scope must keep the behaviour already used for child scope (correction after the 7A review: these pages are `force-dynamic` and rendered per request with `private, no-store`; no code sets `Vary: Cookie`, and none is needed while nothing caches them); with `COMMENTS_ENABLED` off, rendered pages are byte-identical to today.
- Shape: plain text only, 1 to 1000 characters after NFKC and trim, one level of replies (a reply to a reply is refused), display name and relative time only (no avatars, profile links, likes, counts of votes). The display name is chosen at the first comment (1 to 30 characters, NFKC, no `@`, blocked-words, no link-like text via the shared check in `lib/circles/rules.ts`) together with ticking "I have read the community guidelines" (`guidelines_accepted_at`); the email is never shown.
- Trust: `account_trust (account_id PK → accounts ON DELETE CASCADE, level int 0|1 default 0, approved int default 0, rejected int default 0, banned boolean default false, display_name text, guidelines_accepted_at timestamptz, updated_at)`. Level 0: a new comment is `held`; level 1: `published` at once after the checks. After 5 approved with 0 rejections since the last drop the account moves to level 1 (`TRUST_THRESHOLD = 5`, constant); a rejection drops a level (and resets the approved count); banned accounts cannot post. Functions `recordApproval`/`recordRejection` are used by 7B.
- Mechanical checks on every comment, in this order, each with its own refusal code: banned, rate limit (5 per 10 minutes and 40 per day per account), length, blocked words (`lib/items/blocked.ts`), duplicate (same normalised body by the same account in 24 hours, or the same body on the same item), link policy: **below level 1 any link-like text (scheme, `www.`, domain-like) is refused; at level 1 it is accepted but always rendered as plain, non-clickable text**.
- Edit within 15 minutes of creation by the author (re-run all checks; a published comment edited by a level-0 account goes back to `held`); delete any time by the author (status `deleted`, body emptied, row kept so replies keep their place); an account's deletion removes its comments (FK cascade) and, with them, replies under them.
- Statuses: `held | published | hidden | rejected | deleted`. Only `published` is ever shown publicly. The author sees their own `held` comment with a "waiting for review" note and never sees the reason text of a private rejection here (7B emails it).
- Rendering is escape-by-default React text; nothing renders HTML or markdown.
- Migration 021 additive with rollback header. No AI trailers; do not push.

## Review Focus

- A child-profile session, a 13-15 account, a banned account, an unverified account and an anonymous visitor cannot post; a child session's HTML contains no comment section, count or text, including through search, topic and item routes.
- No comment on a Kids world item or `audience = 'kids'` item can be created, read or counted by anyone, whatever the toggles.
- Held, hidden, rejected and deleted comments never reach another viewer (list, count, JSON-LD, search, sitemap, export of someone else's data).
- Forged `item`, `parent`, `comment` or `account` ids in forms change nothing; replies cannot cross items; an author cannot edit after 15 minutes or edit another's comment.
- Account deletion and the member export cover `comments` and `account_trust` (information_schema completeness tests extended, not weakened).

**Interfaces (produces):**
- `checkComment(input: { body: unknown; trustLevel: 0 | 1; now: Date; recent: { sameBodyByAuthor24h: boolean; sameBodyOnItem: boolean; last10min: number; last24h: number } }): { ok: true; body: string; hasLink: boolean } | { ok: false; code: 'length' | 'blocked' | 'link' | 'duplicate' | 'rate' }` (pure).
- `postComment(db, ctx, input: { itemId; parentId?: string | null; body: unknown; displayName?: unknown; guidelines?: unknown }, now): Promise<{ status: 'held' | 'published'; id: string } | { status: 'refused'; code: ... | 'not_allowed' | 'comments_off' | 'no_item' | 'no_parent' | 'name' | 'guidelines' | 'banned' }>` (derives account, age group, consent, banned and level from the server-side context and rows, never the caller; item and parent validated in the same transaction under `FOR UPDATE` on the trust row to make the rate/duplicate checks race-safe).
- `editComment(db, accountId, commentId, body, now): Promise<'saved' | 'held' | 'too_late' | 'not_found' | refusal>`, `deleteComment(db, accountId, commentId, now): Promise<boolean>`.
- `listPublishedComments(db, itemId): Promise<{ id; parentId; displayName; body; createdAt }[]>` (published only, item must allow comments, no author ids/emails), `listOwnPending(db, accountId, itemId)`, `commentsAllowedFor(db, itemId): Promise<boolean>` (world toggle, item override, Kids/`kids` audience always false).
- Trust: `getTrust(db, accountId)`, `recordApproval(tx, accountId)`, `recordRejection(tx, accountId)`, `setTrust(tx, accountId, { level?, banned? })`.
