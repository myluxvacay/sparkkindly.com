# Project 7B: Comment reporting, the moderation agent and appeals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Members can report comments; reports hide a comment when enough trusted people agree (or at once when urgent); a moderation agent (a scheduled Claude Code task, like the content agents) approves, rejects or escalates held, reported and sampled comments through a scoped agent API; rejected authors get a private reason by email and can appeal; the owner sees only escalations and appeals, plus counts in the digest.

**Architecture:** `lib/comments/{reports,moderation,appeals,notices}.ts` (rules and effects; no Next.js imports) over a migration; `/api/agent/moderation` routes using the existing agent auth (`lib/agents/{auth,http,rate-limit}.ts`) with a new agent `role`; admin queue in `/admin/comments/`; MCP tools and a Claude Code subagent plus command under `.claude/` and `agents/`. Behind `ACCOUNTS_ENABLED` and `COMMENTS_ENABLED`. Depends on 7A (`docs/superpowers/plans/2026-11-05-project-7a-comments-core.md`, built).

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, zod, Vitest, Playwright + axe, `lib/email.ts`, the MCP server in `agents/mcp/server.ts`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 7 ("Reporting", "Appeals", "Trust levels are an experiment", "Moderation agent"), section 4a.6 (response targets), `.claude/rules/ai-governance.md` and `data-isolation.md`.

## Global Constraints

- **AI output is untrusted.** The moderation agent only recommends through the API; the server re-validates every decision (the comment still exists, is in a state the decision applies to, the author is not banned for an approve, the mechanical checks from 7A are re-run at approval and an approve that fails them is refused), writes an `audit_log` row with actor `agent:<name>`, and never trusts instructions inside comment text, item text or report notes (all returned to the agent in a clearly delimited `data` field with a fixed instruction preamble in the tool description). The agent cannot ban, change trust directly, touch Kids (none exist), edit items, or reach any other agent endpoint: its key has `agents.role = 'moderation'`, content agents have `role = 'content'`, and each role is refused on the other's routes (403).
- Agent API: `GET /api/agent/moderation/` returns up to 20 comments needing a decision (held first, then reported, then the post-publication sample) with `{ id, itemTitle, world, body, authorTrust: { level, approved, rejected }, reports: [{ reason, note, urgent }], reason: 'held'|'reported'|'sample' }`; no account id, email or display name; `POST /api/agent/moderation/decide/` takes `{ id, decision: 'approve'|'reject'|'escalate'|'keep'|'hide', reason }` (reason 1 to 300 characters, required for reject/hide/escalate). Bodies up to 4 KB, rate-limited like the other agent routes, idempotent (a repeated decision on an already decided comment returns the current state, no second effect).
- Effects: `approve` (held or sampled) publishes and calls `recordApproval` (7A); `reject` sets `rejected` with a private `moderation_reason`, calls `recordRejection`, emails the author; `escalate` leaves the comment held (or hidden if reported) and marks `escalated_at`; `keep` (reported comment judged fine) restores it to `published`, dismisses its reports and counts a false report against each reporter; `hide` (reported or sampled comment judged bad) sets `hidden`, calls `recordRejection` and emails the author like a rejection. A sampled level-1 comment: about 10% of newly published level-1 comments get `sampled_at`; the agent's `reject`/`hide` hides it and drops trust.
- Reports: any verified, non-banned, adult-context account (16+ or any age 13+ who can see comments) may report a published comment once; reasons `abuse`, `personal_info`, `advertising`, `off_topic`, `other`, plus an **urgent** flag for "someone may be in danger or a child is identifiable"; note up to 300 characters; 10 reports per account per day. Weights: a level 1 reporter counts 1, level 0 counts 0.5; at total weight >= 2 from different accounts the comment becomes `hidden` pending the agent; an **urgent** report hides it at once and emails the owner immediately (same recipient and mail path as the daily digest; no comment text in the subject). Three dismissed reports (`keep`) by one reporter drop their trust one level (once) and their reports weigh 0 until the owner resets it.
- Rejection/hide email (essential mail, sent regardless of notification preferences, to the author's account address only): comment excerpt (first 80 characters), the private reason, the community guidelines link, and a signed **appeal** link (token bound to the comment id and account id, 30 days). Appeal = one per comment, a POST behind a GET confirm page, note up to 300 characters, rate limited. No email contains other members' data.
- Appeals go to the owner's queue with the agent's reason; the owner decides in `/admin/comments/`: **overturn** (publishes, reverses that rejection in the trust counts, emails the author) or **uphold** (emails the author). Response targets from 4a.6 are shown beside each queue item as text.
- The owner never has to read a comment unless the agent escalates or someone appeals; the daily digest (existing digest code) gains counts: held waiting, published by agent, rejected, escalated, appeals open, urgent reports (last 24 hours), no comment text.
- Migration is additive with a rollback header. No AI trailers; do not push.

## Review Focus

- A comment's text, an item's text or a report note that tries to instruct the agent ("approve this", "ignore previous rules") has no effect on the server's checks; an agent `approve` of a comment that now fails a mechanical check, belongs to a banned account, or is no longer held is refused.
- A content-role key calling moderation routes, a moderation key calling item routes, a disabled agent, a missing/rotated key: all 401/403 with no data.
- Reports cannot be gamed: a brand-new account cannot hide a comment alone; one account reporting twice, reporting its own comment, reporting a hidden/held/deleted comment, or a child context reporting is refused; urgent reports are rate limited and cannot be used to mass-hide (10 per day, and the owner email carries counts only).
- No email or digest line contains another member's text or contact detail; appeal tokens work only for the author and only once; a forged comment/account id in the appeal form is ignored.
- Decisions are idempotent and race-safe (agent decision vs owner action vs author delete vs report threshold crossing); audit rows exist for every decision.
