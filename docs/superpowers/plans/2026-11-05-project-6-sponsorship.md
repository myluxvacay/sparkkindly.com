# Project 6: Light sponsorship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The owner creates sponsors and attaches a sponsorship to a topic, world or item in `/admin`; one plainly-labelled sponsor line appears on matching items rated `adults` for viewers who may see it (anonymous visitors and signed-in accounts 18 and over, never a child profile or anyone under 18, never on Kids or `all` items); clicks are counted without identifying anyone.

**Architecture:** `lib/sponsorship/` (rules, eligibility, selection, clicks; no Next.js imports) over a small additive migration (the `sponsors` and `sponsorships` tables already exist from Project 1); a server-rendered `SponsorLine` component on the item page; a click route `/go/<id>/`; a plain-language disclosure page `/sponsorship/`; admin page `/admin/sponsors/` with audited actions. Behind `SPONSORSHIP_ENABLED` (off everywhere; independent of `ACCOUNTS_ENABLED`, which only adds the under-18 check when a session cookie is present).

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, Vitest, Playwright + axe. Existing: `lib/public/{reads,scope}.ts`, `lib/accounts/{scope-next,context,policy}.ts` (age group), `lib/items/gates.ts` (`isSafeSourceUrl`), `lib/admin/actions.ts`, `lib/jobs`, item page.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 6, section 4a.3 (sponsorship rules, excluded categories, disclosure wording), 4a.5 (never to under-18s or children) and `.claude/rules/{data-isolation,security,accessibility}.md`.

## Global Constraints

- **Eligibility (all must hold, decided on the server, fail closed):** `SPONSORSHIP_ENABLED`; the item is `published`, audience exactly `adults`, not in the Kids world, risk tier not `kids`; the viewer is anonymous OR a signed-in account whose derived age group is `adult` and whose active context is the adult (not a child profile). Any session cookie that cannot be resolved (lookup error), a teen account (13-17), a consent-pending account, a child profile: **no sponsor line, no sponsor request, no click route for them**. A circle with a child profile never reaches an adults item (4C), and nothing in a circle page, set, share prompt, email, JSON-LD, search result or sitemap ever carries sponsorship.
- **One line, one place:** at most one sponsor line per item page, under the title; the plain site typography (no banner, pop-up, image, logo, script, iframe, tracking pixel; no third-party request at all: the sponsor's link is an ordinary anchor `rel="sponsored noopener noreferrer"` to our own `/go/<id>/` redirect). The `logo` column is not used in this project.
- **Disclosure in plain words next to the link, from two fixed templates chosen by `sponsorships.kind`:** `affiliate` -> "SparkKindly earns a commission if you buy through this link."; `supported` -> "This topic is supported by <sponsor name>. <sponsor name> had no say in what we publish." (a `world` target says "This section"; an `item` target says "This piece"). The owner-entered `label` is the link text only (1 to 60 characters); the disclosure sentence cannot be removed or edited per sponsorship. A link to `/sponsorship/` (disclosure page explaining the whole arrangement) sits in the same line.
- **Owner-created, owner-approved only:** no self-serve portal; sponsors never see content before publication and cannot request changes (stated on the disclosure page). Sponsor fields: name (1 to 80), link (https only, public host, no credentials, `isSafeSourceUrl`), `category` from a fixed allowed list (education, books, software, services, health-and-wellbeing-general, finance-education, travel, food, other-approved) with the **excluded categories of 4a.3 not selectable** (gambling, alcohol, tobacco and vaping, weapons, adult content, payday lending, cryptocurrency and get-rich schemes, supplements and weight-loss products, political and religious organisations, anything marketed to children) and a required confirmation box "this sponsor is not in an excluded category and is not marketed to children", recorded in the audit row.
- **Relevance:** a sponsorship targets exactly one of item, topic or world (existing CHECK); selection precedence item > topic > world, then most recently started; only within `starts_on`/`ends_on` (inclusive, UTC dates, NULL = open) and the sponsor's `active_from`/`active_to`; an expired or ended sponsorship never renders. The owner can end a sponsorship at once.
- **Clicks:** `/go/<id>/` re-checks eligibility for the request (same rules, so a link copied to a child's session redirects to the home page instead of the sponsor), increments `click_count` with one atomic UPDATE, sends `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, no cookies, and redirects 302 to the stored https link. Per-network rate limit (60 per hour) so a script cannot inflate counts cheaply; the count is documented as an upper bound (no identifiers kept, bots count). No click log rows, no IP storage.
- **Contributed items** may carry sponsorship under these same rules (the contributor terms already say so).
- **Privacy:** nothing about the viewer is stored; no new cookie; the existing e2e (no third-party requests, no storage identifiers on Kids pages) stays green and a new assertion checks that no Kids, `all` or teen/child view of any page contains the sponsor name or link.
- Migration additive with rollback header; add `sponsors.category text`, `sponsors.confirmed_at timestamptz`, `sponsorships.kind text NOT NULL DEFAULT 'supported' CHECK in ('supported','affiliate')`, `sponsorships.ended_at timestamptz`. No AI trailers; do not push.

## Review Focus

- A child profile, a 13-17 account, a consent-pending account, a failed session lookup and any Kids/`all`/non-published item never receive the sponsor line, the sponsor name or link in any response, and `/go/<id>/` never redirects them.
- No path writes or reads sponsor data for ineligible viewers (cache keys, JSON-LD, search, sitemap, share prompt, mail, circle pages, RSS-like outputs); with `SPONSORSHIP_ENABLED` off every page is byte-identical to today.
- Sponsor link safety: only https to a public host; no open redirect (the redirect target is the stored link of an existing active sponsorship id, never a parameter); `rel="sponsored noopener noreferrer"`; no script or image.
- Admin: only an admin with CSRF can create/attach/end; excluded categories cannot be saved by any request shape; every change audited; clicks cannot be edited.
- Dates: a sponsorship ending today still shows today and not tomorrow; time-zone independent (UTC dates); overlapping sponsorships pick exactly one by the precedence rule.
