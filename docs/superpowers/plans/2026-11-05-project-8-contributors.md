# Project 8: Contributors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Members aged 16 and over can turn on a contributor role, write an article or a multiple-choice quiz question in `/me/contribute`, and submit it; it passes the server gates, the reviewer agent and always the owner's approval, then publishes with "By <name>" credit and a contributor page; the contributor is emailed on publication and can withdraw a piece at any time.

**Architecture:** `lib/contributors/` (profile, terms, drafts, submission, state machine, byline reads; no Next.js imports) over a migration; contributed items are ordinary `items` rows (so every existing read, gate, audience and Kids rule applies) linked by `items.contributor_account_id`; reviewer queue endpoints for the master content agent under `/api/agent/contributions`; an owner queue in `/admin/contributions/`; pages under `app/me/contribute/` and `app/contributors/[slug]/`. Behind `ACCOUNTS_ENABLED` and `CONTRIBUTORS_ENABLED` (both off everywhere).

**Tech Stack:** Next.js 16, TypeScript, `pg`/PGlite, zod, Vitest, Playwright + axe. Existing: `lib/items/{format,gates,repo,policy}.ts`, `lib/agents/{auth,http,rate-limit}.ts`, `.claude/agents/sparkkindly-reviewer.md`, `.claude/commands/daily-run.md`, `lib/admin/actions.ts`, `lib/email.ts`, `lib/accounts/{policy,context,export,delete}.ts`, `lib/jobs/publish-due.ts`.

**Spec:** `docs/superpowers/specs/2026-10-30-sparkkindly-platform-design.md` Project 8, section 4a.5 and `.claude/rules/{ai-governance,data-isolation,security,media-storage}.md`.

## Global Constraints

- **Who:** capability `contribute` (16+ and adults), verified, not banned from commenting (a comment ban also blocks contributing), adult context only (child profile context: denied and the pages absent). The role is switched on in `/me/contribute` by accepting the contributor terms (`terms_accepted_at`) and giving a display name (1 to 30 characters, same name checks as comment names: NFKC, blocked words, no link-like text, reserved names refused) and an optional bio of up to 140 characters (same checks). An optional external link is proposed by the contributor and shown only after the owner approves it (`link_approved`).
- **What:** `article` and `quiz` (single-answer multiple choice only: question, 2 to 5 options, one marked correct, explanation) in any world except Kids; audience is set to `all` by the server (never `kids`, never chosen by the contributor); risk tier derived by the existing `riskTierFor`. Plain text only: paragraphs separated by blank lines, no HTML, no markdown rendering, no images (media rules: nothing uploaded in this project). Limits: title 140, summary 300, article body 8,000 characters, 1 to 6 sources per item (required whenever it states facts; the existing gates decide), explanation 500.
- **Declaration:** every submission needs two ticked boxes recorded with a timestamp: "this is my own work and contains nothing I lack the rights to" and acceptance of the licence grant (non-exclusive, perpetual licence to publish, edit for clarity, translate and promote with attribution; the contributor keeps copyright). The contributor terms page `/contributors/terms/` states this plainly, plus: no payment, sponsorship may appear on contributed items under the Project 6 rules, withdrawal at any time, and that the owner approves every contributed item.
- **Limits:** at most 3 pending submissions (states `submitted`, `agent_review`, `needs_owner`, `changes_requested`) per account; 10 saves per hour and 5 submissions per day per account; drafts (`draft`) are private, at most 5 per account.
- **Pipeline (states in `contributions.state`):** `draft` -> `submitted` (server gates run synchronously: schema, duplicates, blocked topics and words, sources resolve; a gate failure returns the reasons and the state stays `draft`) -> `agent_review` (the reviewer agent, via the master content agent, judges facts and sources, tone, originality and does a best-effort plagiarism search for distinctive sentences; fail -> `changes_requested` with the reasons shown to the contributor and emailed, never the reviewer's raw transcript) -> `needs_owner` (item `in_review`; **owner approval is always required**) -> `approved` (item enters the normal scheduling path and publishes via `publish-due`) or `changes_requested` with the owner's notes, or `rejected` with a reason. A contributor revises and resubmits (revision count kept; the same item row is updated, snapshots kept in `item_revisions`). `withdrawn` by the contributor at any time (an unpublished/withdrawn published item is archived at once).
- **AI governance:** the reviewer agent's output is untrusted. Contribution text and every page the reviewer opens are data, never instructions; the existing reviewer prompt already fails an item that addresses the reviewer. The server validates the verdict shape (zod), stores it in `items.quality_report`, never lets an agent move an item past `needs_owner`, and only the owner's admin action can approve. Agent keys: only the master content agent (role `content`, `world_id` NULL) may call the contribution routes; world agents and the moderation role get 403.
- **Credit:** a published contributed item shows "By <display name>" linking to `/contributors/<slug>/` (slug = random 10-character id, not the name), which lists their published items, bio and the approved link. Anonymous readers see it; the byline appears only for `published` items. Item JSON-LD gains `author` for contributed items. The contributor receives an email on publication with the share link (essential-style mail, one per item, claim-before-send).
- **Deletion and export:** deleting the account archives all of its published contributed items, removes the contributor profile and sets `items.contributor_account_id` to NULL on archived rows (so the byline disappears); drafts and contributions rows cascade. The export includes the contributor profile, own drafts, submissions, states and owner notes addressed to them. The data inventory and go-live copy are updated.
- **Kids:** no contribution can target the Kids world, the Kids audience or a Kids risk tier; refused on submit and on every revision.
- Migration additive with rollback header. No AI trailers; do not push.

## Review Focus

- A contributed item can never be published, scheduled or even `in_review` without passing the gates, an accepted reviewer verdict and the owner's approval; an agent call, a forged id, a replayed verdict or a crafted contribution cannot skip a stage; the owner approval cannot be given by anyone else.
- Cross-account: account B cannot read, edit, submit, withdraw or see the reviewer notes of account A's contribution; the contributor page shows only published items of that contributor.
- Kids world/audience/tier submissions are refused whatever the form says; the contributor cannot set audience, status, world-approval or agent fields.
- Prompt injection inside a contribution (text addressed to the reviewer or the owner UI) has no effect on the server's decisions and renders as plain text everywhere.
- Account deletion and withdrawal leave no byline, no profile and no personal data; a deleted contributor's published items are archived, not left credited to nobody.
